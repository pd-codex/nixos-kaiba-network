Control path: certificate identity constrains the name; idempotency and generation conditions constrain the write.

Data path: after resolution, HTTPS goes directly from the client to the device—not through the controller or DNS origins.

02 / Guarantees

Specific controls, not security theater.

A

Identity-bound updates

The client certificate determines the device and DNS owner. Request bodies cannot choose a hostname, zone, TTL, or record type.

B

Durable intent, observable convergence

Accepted, origin-applied, and publicly-observed remain distinct states. A 202 means intent is durable—not that DNS has already converged.

C

A constrained DNS writer

Only the publisher owns the TSIG update credential. P0 is writable; P1 and public secondaries remain authoritative-only and non-recursive.

D

Evidence you can inspect

The topology records assertions, answers, serials, snapshots, and normalized evidence—even when a functional assertion fails.

03 / Convergence

Acceptance is not publication.

A generation advances only as each independently observable condition becomes true.

STATE 01

accepted

The controller has durably committed desired state and the idempotency result.

STATE 02

origin-applied

The publisher's atomic authenticated update has succeeded at writable origin P0.

STATE 03

publicly-observed

Every configured public authority agrees with the generation's complete address set.

04 / Device API

The request cannot choose its own name.

A URI SAN such as spiffe://kaiba.network/device/001 maps to pi-001.kaiba.network. The body supplies only the device's canonical, complete address set. A strong generation precondition prevents delayed writes from replacing newer state.

Exact retries return the recorded result. Reusing an idempotency key for different content or a different precondition fails instead of silently changing intent.

! PILOT BOUNDARY

The production boundary is part of the design.

The executable topology uses kaiba.test, a simulated parent authority, test-only credentials, and public-secondary emulators. It never contacts Namecheap or changes kaiba.network. The current device agent still uses a file-backed private key.

Real provider integration and SLAs, Internet and NAT behavior, ACME, DNSSEC, safe automatic origin promotion, redundant controllers, fleet-scale operation, production credentials, deployment, and monitoring remain deferred.
