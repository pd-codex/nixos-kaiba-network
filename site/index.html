01 / Product

One device trust story. Two focused systems.

Provisioning establishes what the device is allowed to become. DNS uses its operational identity to control the name it is allowed to publish.

SECURE PROVISIONING EXPERIMENTAL PREFLIGHT

01

Observe before you mutate.

Bind an operator lane to exactly one target, acquire tightly constrained metadata, normalize it under a strict profile, and preserve the result as partial qualification evidence.

  • Non-persistent live probe and offline evidence evaluation
  • Digest-pinned tool, firmware, profile, and bundle inputs
  • One interface codebase for the local station and Pages simulation
  • Explicit mutation, attestation, and hardware-qualification boundaries

IDENTITY-BOUND DNS EXECUTABLE PILOT

02

A stable name with a constrained writer.

Turn a device's mTLS identity and complete address set into durable desired state, then project it through a credential-isolated publisher and observe convergence at redundant public authorities.

  • Certificate identity determines the only writable DNS owner
  • Generation conditions and idempotency make retries explicit
  • RFC 2136 credentials stay in a separate publisher service
  • Seven-VM tests record publication and failure evidence

! PRODUCT BOUNDARY

A working pilot with an explicit road to production.

The DNS control plane is exercised end to end in an isolated test domain. The provisioning implementation stops at correlation and partial preflight: it executes signed recovery code in volatile RAM but does not change persistent target state, install keys, enroll credentials, or authorize a device.

Production RA and CA integration, inventory activation, transaction coordination, irreversible device security changes, protected signing, complete attestation, Internet provider integration, fleet deployment, and monitoring remain outside the current executable scope.
