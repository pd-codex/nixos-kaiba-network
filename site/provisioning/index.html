01 / What runs today

A narrow executable slice with hard edges.

Acquisition, normalization, and policy evaluation remain separate so future hardware adapters can change without weakening the transaction semantics.

A

Offline evaluation

Import bounded metadata from a file or standard input and receive the same normalized assessment without touching USB or starting a subprocess.

B

Lane-bound live probe

Require a stable lane ID and exact USB path. Reject missing, multiple, replaced, or unexpected targets instead of auto-selecting hardware.

C

Immutable probe inputs

Revalidate the pinned tool and the exact two-file metadata-only recovery bundle before each run. Reject extra files, symlinks, and mutation directives.

D

Strict evidence policy

Normalize revision, identity, key-hash, JTAG, boot ROM, and EEPROM observations under a digest-bound profile. Unknown upstream fields make the baseline indeterminate.

E

Deterministic result

Emit one JSON observation with evidence and profile digests, a domain-separated target fingerprint, typed findings, and unconditional safety fields.

F

Shared station interface

Run the same HTML, CSS, controller, and transport in the loopback kiosk and GitHub Pages. Pages traverses a generated mock graph and has no target privilege.

02 / Safety contract

A passing preflight is permission to learn more—not to mutate.

ALWAYS ASSERTED IMPLEMENTED

What the result can establish

  • Evidence correlates to one explicitly selected physical path
  • Observed class fields match or reject the experimental Pi 5 profile
  • Observable baseline facts pass, fail, or remain indeterminate
  • The target may become eligible for further reversible qualification
  • Tool, bundle, profile, and evidence inputs are digest-bound
NEVER IMPLIED OUT OF SCOPE

What the result cannot establish

  • Device authentication, remote attestation, or inventory ownership
  • The full unprovisioned state or absence of every device secret
  • Storage contents, protected key rows, or every debug path
  • Firmware authenticity beyond the pinned acquisition inputs
  • Authorization for OTP, EEPROM, key, boot, or any other persistent change

03 / Target transaction

The production ceremony is a durable transaction.

These stages are the platform-neutral design contract. Except for the preflight observations above, they are not yet implemented by the station.

Create transaction

Reserve the logical ID and asset; bind the operator, policy, nonce, tools, and claim lease.

02 PARTIAL SLICE

Claim + validate

Identify one candidate and establish every observable baseline fact before any write.

03 TARGET DESIGN

Approve commit plan

Bind independent approval to the target, profile, artifacts, ordered operations, and postconditions.

04 TARGET DESIGN

Secure + create keys

Establish boot, update, storage, debug, and protected signer posture; keep private material on target.

05 TARGET DESIGN

Enroll + stage

Bind bootstrap authentication and proof of possession; let the RA assign identity and the CA issue.

06 TARGET DESIGN

Verify + activate

Prove the installed key and certificate work, record independent evidence, activate, audit, and release.

04 / Provisioning station

The station executes policy. It does not own fleet authority.

A dedicated station isolates physical target access and short-lived bootstrap capability from everyday operator and development machines.

CONTROLLED STATION

One operator. One lane. One claimed target.

A generic orchestrator should enforce ordering, journaling, retry, approval, and postconditions while a pinned platform adapter performs hardware-specific work. A privileged lane guard exposes only the current target-facing interface.

Coordinator + inventory

Registration + certification authorities

Bundle + policy authority
Approve immutable software, firmware, profiles, adapters, and ordered operations.
Verifier + audit service
Appraise postconditions and retain provenance independently of the station.
! IMPLEMENTATION BOUNDARY

The interface is shared. The production backend is not here yet.

The loopback kiosk and Pages demo render deterministic mock station states. They do not access USB, run the probe, handle secrets, authenticate operators or devices, call an RA or CA, or perform a mutation. Interface parity does not imply production workflow authority.

Still required: coordinator and inventory services, signed production bundles, mutating adapters and lane guards, protected key integration, RA and CA enrollment, independent verification, credential activation, durable audit, and sacrificial-board hardware qualification.
